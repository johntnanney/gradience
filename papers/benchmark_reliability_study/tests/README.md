## Run instructions

From the paper directory, with the pip-resolved dependencies installed
(study `pyproject.toml` plus `statsmodels`, `seaborn`, `matplotlib`,
`jsonschema`, `torch` for the GPU-test path):

```bash
cd papers/benchmark_reliability_study
python -m pytest tests/ -v --tb=short
```

Or for a quieter run:

```bash
python -m pytest tests/ -q
```

Or with coverage:

```bash
python -m pytest tests/ --cov=gradience_study --cov=scripts \
  --cov-report=term-missing
```

To regenerate the fixtures from scratch (for example after a schema bump):

```bash
python tests/fixtures/make_fixtures.py
```

The generator is idempotent — re-running produces byte-identical outputs.

## Known limitations

### 1. `test_mmlu_subject_decomp.py::test_mixed_effects_path_used_on_well_conditioned_fixture` is statsmodels-version-dependent

**Symptom.** Asserts that the cascade selects the `mixed_effects`
fallback level (rather than dropping through to `anova`) on the canonical
MMLU fixture. With `statsmodels==0.14.6`, the MixedLM fit reports
non-convergence and the cascade correctly falls back to ANOVA.

**Status.** Output correctness is unaffected — the ANOVA fallback
produces the right variance components, and the cascade-descent path
is exactly what `IMPLEMENTATION_DEVIATIONS.md` D-09 (LPM-not-logistic)
and the cascade design contemplate. The test is asserting a stronger
property — that the mixed-effects path *converges on the well-conditioned
fixture* — that is statsmodels-version-sensitive.

**Resolution options (none triggered, recorded for future work):**
- (a) Loosen the assertion to `fallback in {"mixed_effects", "anova"}`
  and add a separate test that exercises the cascade-descent log entry.
- (b) Make the fixture more numerically well-conditioned so MixedLM
  converges across recent statsmodels versions.
- (c) Pin statsmodels to a version where this fixture converges.
  Discouraged: locks us into a stale dependency for a one-test issue.

**Recommendation.** Option (a) is the smallest change and matches the
spec's framing — the cascade is allowed to descend, and descending is
not a regression.

### 2. GPU-only inference paths exercise mock models, not real weights

The `score_ll_norm` and `score_generate_parse` functions in
`scripts/gpu_inference.py` are tested with hand-rolled tokenizer + model
fakes that produce deterministic logits. Real-weight verification is
delegated to the pod-side smoke run (`SPEC_GPU_v0_1.md` §12) and the
full pipeline. The mock tests catch contract violations and dispatch
errors but cannot catch numerical-precision issues that only surface
on real weights.

### 3. `test_reproducibility_trace.py::test_trace_summary_section_consistent` may skip when `mock h1_test.json` is unavailable

The test uses `pytest.skip("mock h1_test.json not available")` if the
fixture-bundle's `h1_test.json` artifact is missing. Under the current
fixture set this artifact is present; the skip is defensive against
fixture-set drift. If you see this skip in a run, regenerate fixtures
via `make_fixtures.py`.

### 4. Statsmodels and seaborn are not in the study's `pyproject.toml`

The CPU-pipeline tests for variance components, ranking stability,
MMLU subject decomp, and report generation depend on `statsmodels`,
`seaborn`, and `matplotlib`. The study's `pyproject.toml` lists these
under the analysis-time dependencies (Section 8 of `LOCK_NOTES.md`),
but the test suite expects them to be present. On a fresh environment,
install via:

```bash
pip install statsmodels==0.14.6 seaborn matplotlib
```

(or use the analysis-environment `requirements.lock` once it lands).
